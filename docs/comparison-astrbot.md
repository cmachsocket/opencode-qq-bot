# 与 AstrBot 的能力对比（候选清单）

> 状态：**待评审**。本文档是第二个参照物，候选条目只列 `docs/comparison-qq-bridge.md` 里**没有**的增量；
> 两份文档重复的条目不在这里重复列，见「三、与 qq-bridge 文档的对照」。
> 尚未实现的条目 = 早期阶段的待办，不等于缺陷，优先级见「六、评审记录」。

## 项目定位与职责边界

本项目做的是 **QQ 聊天的生命周期管理**：接消息 → 渲染 → 分发到会话 → 收模型回复 → 发回 QQ，
外加会话绑定、忙碌判定、失败恢复、提醒、主动说话、收藏表情这些"让机器人一直在群里活着"的机制。

AstrBot 不是同类竞品：**它自己就是 agent runtime**——自带 44 个模型 provider、工具循环、OS 级沙箱、
向量库 + BM25 检索、上下文压缩、subagent、skills、persona、插件市场和一个 30k 行的管理面板。
本项目则只做 QQ ↔ OpenCode 的胶水，agent runtime 是 OpenCode。

因此 AstrBot 有而我们没有的东西，大多**不是缺口，而是它替 OpenCode 做了**：

| 领域                                 | 归谁                                         |
| ------------------------------------ | -------------------------------------------- |
| 模型接入、工具循环、重试、上下文压缩 | OpenCode                                     |
| 记忆 / 知识库 / 检索                 | OpenCode（可用 opencode-mem / opencode-dcp） |
| 沙箱与本地执行环境                   | OpenCode                                     |
| OneBot 其余动作面                    | SnowLuma MCP（可选，read 模式）              |
| token 用量与成本核算                 | OpenCode                                     |

判定准则：改进项若落在"模型看到什么 / 记住什么 / 怎么想 / 在哪执行"上，先问它是不是框架职责。

**这条准则在本次对照里淘汰掉了一大批候选项**：AstrBot 的 provider 回退链、上下文压缩阈值、
BM25+向量融合检索、MCP stdio 沙箱，都不属于本项目该抄的清单。
（C1 的"调用链追踪"不在此列——要的是自己会话的可观测性，不是把 OpenTelemetry 整套搬过来。）

## 对比对象与前提

|      | 本项目 `opencode-qq-bot` | 对照项目 `AstrBot`                                    |
| ---- | ------------------------ | ----------------------------------------------------- |
| 形态 | OpenCode V2 插件（TS）   | 独立 Python 进程，自己充当 agent runtime              |
| 规模 | `src/` 约 7k 行          | 797 个 .py / 265k 行（含 98k 行测试、30k 行面板后端） |

| 依赖 | 12 个                    | 80+ 个（含 faiss、jieba、fastapi、vue 工具链）        |
| 许可 | CC-BY-NC-SA-4.0          | AGPL-3.0-or-later（传染，仅比较不抄代码）             |

## 三、与 qq-bridge 文档的对照

以下条目在 `docs/comparison-qq-bridge.md` 已列出，本次对照**独立确认**，不重复列入候选：

| 条目                | qq-bridge 依据                             | AstrBot 依据                                                                        | 本项目现状                                                                |
| ------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| A1 出站速率限制     | `maxSendPerMinute=8` / `maxSendPerHour=60` | pipeline `RateLimitStage` 30 次 / 60 秒固定窗口                                     | **我们已实现**（`src/rate-limit.ts`）；只差 `stall` 档                    |
| A2 出站敏感信息拦截 | `src/sensitive.js` + 已知令牌表            | **也没有**（`error_redaction.py` 只用于日志与诊断包）                               | **我们已实现**（`src/sensitive.ts`，用 flare-redact）                     |
| A3 注入净化         | `sanitizeUntrustedText` + 相对时间         | **也没有**（只有 `<persona_instructions>` 框架 + 两处工具描述里的"当作不可信数据"） | **我们已实现**（`src/model-view.ts`）                                     |
| A5 SSRF             | DNS 全量校验 + 连已校验 IP + 端口白名单    | **更弱**：全库无 SSRF 逻辑，且证书校验失败会 fallback `CERT_NONE` 继续下载          | **我们已实现**（`src/safe-fetch.ts`）                                     |
| A6 媒体路径白名单   | 语音库白名单 + 路径穿越防护                | 有（文件访问用 `O_NOFOLLOW` + 目录 fd 遍历，拒符号链接与硬链接）                    | **我们已实现**（`src/media-path.ts`）                                     |
| B5 出站文本质量     | `md-to-plain.js` + 代理对安全切分          | 无专门处理（切分靠正则 `.*?[。？！~…]+`）                                           | **我们已实现**（remove-markdown + `Intl.Segmenter`）                      |
| B6 失败兜底         | `reportTurnFailure()` 统一文案 + 节流      | Persona `custom_error_message`                                                      | **我们已实现**（`notifyFailure` + 冷却），文案不可配见 B4                 |
| B7 通知事件         | 处理撤回、戳一戳、成员增减                 | **只做了 poke**（`notice` + `sub_type=="poke"` → `Poke` 组件）；**撤回两边都没有**  | **已实现**（`events.subscribe` / `events.notices`）；撤回不复述被撤回内容 |

AstrBot 侧**没有**、但本项目已经有的：A1 出站限流、A2 出站敏感信息拦截、A3 注入净化、A5 SSRF、A6 媒体路径白名单、B5 出站文本质量、B6 失败兜底、撤回消息（AstrBot 全库 `delete_msg` / `recall` / `撤回` 零命中；我们有 `delete_message` 工具且限制只能撤自己发过的）。

## 四、参照时的注意事项

### 我们已经更严的三处

| 方面               | AstrBot                                                                                            | 本项目                                                                                                                   |
| ------------------ | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 媒体下载的传输安全 | 证书校验失败会 fallback `CERT_NONE`（关掉 TLS 校验）继续下载；不限制跳转                           | `request-filtering-agent` 在连接层判定公网地址，端口白名单 `[80,443,8080,8443]`，**3xx 直接失败不跟随跳转**，无 TLS 降级 |
| 工具面默认值       | 非内置工具默认权限是 `member` = **开放**（含 shell / 文件 / ipython / 浏览器控制），靠 OS 沙箱兜底 | 已拦 `question`（避免 TUI 弹窗阻塞会话）；其余工具的处置待评审                                                           |
| 静态类型           | pyright `basic` 模式，且 `pyrightconfig.json`（3.12）与 `pyproject.toml`（3.10）**版本不一致**     | TS strict + zod schema 驱动配置                                                                                          |

### 不该照抄的三处

- **默认开放本地执行类工具**。AstrBot 依赖 bubblewrap / seatbelt / AppContainer 兜底；我们没有这一层，且工具面收敛本身还在待评审。
- **降级式安全策略**。证书校验失败就关校验、默认密码可在 loopback 跳过、JWT 有效期 7 天——都是"方便优先"的取舍。
- **配置与密钥的存放方式**。AstrBot 把密码哈希、jwt_secret、totp secret、provider API key、平台 secret **明文存进 JSON**；OpenCode 的配置与本项目的 `.env` 处理方式要更小心。

## 五、已确认缺陷

本次对照**没有发现新的本项目缺陷**。qq-bridge 文档里的 D1（只含 QQ 表情的消息被整条丢弃）已修复。

AstrBot 侧有一个同类缺陷值得记一笔：它的 QQ 适配器把 `mface` 段**静默丢弃**（`aiocqhttp_platform_adapter.py:398-399`），
和我们的 D1 是同一类问题——门卫把渲染器本来能处理的内容挡在了外面。
