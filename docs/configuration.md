# 配置参考

插件选项优先于环境变量，环境变量优先于默认值。完整列表见 [README](../README.md#配置)，
这里补充取值规则与边界行为。

## 配置作用域

插件配置分两层：

- **全局配置项**：插件选项、环境变量与内置默认值，对插件处理的所有聊天生效。
- **会话配置项**：`chat-overrides.json` 里按聊天写的字段，只覆盖命中的目标；没写的字段回落到全局值。

本页其余小节介绍全局配置项，会话配置项见[会话覆盖](#会话覆盖)。

## 取值规则

- **布尔**：`true` / `false`、`1` / `0`、`yes` / `no`、`on` / `off`，不区分大小写。
  写错（例如 `maybe`）会回退到默认值并输出告警。
- **数值**：直接写数字，例如 `250`、`0.01`。写错会回退到默认值并输出告警。
- **群号 / QQ 号**：逗号分隔，例如 `123,456`；插件选项里写成数组。重复项会去重，
  非正整数会被忽略并告警。
- **模型**：`provider/model` 或 `provider/model/variant`。
  写错会回退到默认模型并输出告警。
- **未知配置项**：顶层和 `napcat`、`access`、`proactive`、`wake`、`reply`、`trace`、`reminder`、`keepAlive`、`history`、`rateLimit`、`sensitive`、`events`、`log`、`media` 下的未知键会输出告警，
  不会被静默忽略。

| `reply.minDelayMs`                  | 大于等于 0 |
| `reply.maxDelayMs`                  | 大于等于 0 |
| `reply.segmentChars`                | 大于等于 1 |
| `reply.forwardThresholdChars`       | 大于等于 0 |
| `trace.maxSizeMb`                   | 大于等于 1 |
| `trace.retentionDays`               | 大于等于 1 |
| `keepAlive.seconds`                 | 大于 0     |
| `history.count`                     | 大于等于 0 |
| `rateLimit.maxPerMinute`            | 大于等于 0 |
| `rateLimit.maxPerHour`              | 大于等于 0 |

越界值会回退到默认值并告警。

## 配置告警

写错的配置项不会静默失效，插件启动时会逐条输出告警：

```
[qq-bot] warn QQ_SEND_DELAY_MS 不是合法的数字：abc
[qq-bot] warn QQ_BOT_MODEL 格式无效：openai（应为 provider/model[/variant]）
```

旧配置名（`QQ_TARGET_GROUPS` / `QQ_TARGET_USERS`、插件选项 `groups` / `users`）的迁移提示
带 `【迁移】` 前缀，启动时按 error 级别输出；未迁移时机器人不会响应任何消息。

`proactive.tickSeconds` 必须是正数，否则心跳会退化成毫秒级热循环，非正数会回退到默认值。
`startProbability` 与 `probabilityPerHour` 表示目标每小时概率，实际每个心跳的触发概率会按
`tickSeconds` 换算，修改心跳间隔不会改变整体触发频率。

## 保活

OpenCode 默认在 location 空闲 60 分钟后卸载它的服务，插件随之被卸载，
NapCat 连接断开后机器人就不再响应。

| 手段                                      | 作用                                                         |
| ----------------------------------------- | ------------------------------------------------------------ |
| `experimental.location_idle_timeout`      | OpenCode 自身的配置，设为 `false` 就不再自动卸载（推荐）     |
| `keepAlive.enabled` / `keepAlive.seconds` | 插件的保活心跳，周期性写回会话元数据来刷新 location 空闲计时 |

`keepAlive.seconds` 必须小于 OpenCode 的 location 空闲超时（默认 3600 秒），
心跳间隔过大就来不及刷新。插件的心跳跑在一个不绑定 QQ 目标的专用会话上，
不影响群聊会话，也不消耗模型调用。

插件卸载时会删掉这个专用会话，不会在项目目录里留下垃圾；取得会话时也会请求归档，
让它不出现在会话列表里——上游插件接口目前忽略归档请求，在它支持之前该会话仍会显示，
插件会在日志里说明这一点。

## 历史补齐

会话第一次投递消息前，插件会把之前的聊天记录以 `<history>` 块拼在首轮提示前面。

| 情况                     | 补哪些消息                                       |
| ------------------------ | ------------------------------------------------ |
| 新建会话                 | 最近 `history.count` 条                          |
| 复用上次的会话（重启后） | 上次投递到的位置之后的消息，也就是重启期间的增量 |

`history.count` 为 `0` 表示关闭历史补齐。补齐只在每个目标的第一次投递时做一次，
失败不会留下“已经补过”的标记，下一轮会重试。本次运行里已经实时处理过的消息不会被重复补进来。

## 唤醒判定

群里什么时候必须回复由「全局唤醒策略 + 会话覆盖」一起决定，私聊永远回复。

| 配置项                | 默认值  | 含义                                                 |
| --------------------- | ------- | ---------------------------------------------------- |
| `wake.prefixes`       | `["/"]` | 全局唤醒前缀，逗号分隔；消息以这些前缀开头就必须回复 |
| `wake.ignoreAtAll`    | `true`  | 是否忽略 @全体成员                                   |
| `wake.replyToSelf`    | `true`  | 回复机器人自己的消息是否必须回复                     |
| `wake.ignoreAtOthers` | `true`  | 群里第一个 @ 指向别人时是否不唤醒机器人              |

判定顺序：

1. 私聊一律必回。
2. 会话覆盖里的 `wake` 优先：`none` 完全不理，`all` 每条都必回。
3. 消息里直接 @ 了机器人 → 必回（`mention`）。
4. 群里第一个 @ 指向的是别人 → 这条消息不是跟机器人说的，不唤醒也不插话。
5. 命中全局前缀 → 必回（`prefix`）；`wake: prefix` 的聊天只看自己写的前缀。
6. @全体成员 → `wake.ignoreAtAll` 为 `false` 时必回（`at_all`），默认忽略。
7. 回复了机器人自己 → `wake.replyToSelf` 为 `true` 时必回（`reply`）。
8. 其余情况不强制回复，模型可以自行决定要不要说话。

例如默认配置下，`@某人 /ping` 虽然以全局前缀 `/` 开头，但第一个 @ 指向别人，
第 4 步就先判定为「不是跟机器人说的」，不会因为前缀命中而触发回复。
`wake: prefix` 的会话在第 5 步直接返回，不再检查 `replyToSelf`、@全体成员与全局前缀。

## 分段回复

模型回复太长时按段发出去，段与段之间留一点随机间隔，看起来更像人在分条打字。

| 配置项                        | 默认值 | 含义                                                 |
| ----------------------------- | ------ | ---------------------------------------------------- |
| `reply.minDelayMs`            | `0`    | 分段之间的随机等待下限（毫秒）                       |
| `reply.maxDelayMs`            | `0`    | 分段之间的随机等待上限（毫秒），`0` 表示改用固定间隔 |
| `reply.segmentChars`          | `150`  | 单段最多多少字，超出就拆成多段发送                   |
| `reply.forwardThresholdChars` | `1500` | 超过多少字改用合并转发，`0` 表示不转换               |

- 配了 `reply.maxDelayMs` 就在区间里随机等待；没配时沿用 `sendDelayMs` 的固定间隔，行为与旧版一致。
- 超过 `reply.forwardThresholdChars` 的回复改用合并转发，一条消息占一条，不刷屏；
  转发节点太长时再拆成多个节点。
- 未超过阈值但分段数超过当前剩余限流额度时，也会改走合并转发，避免只发出半截消息。
- 拆分与合并转发都只影响出站形式，不改变内容。

## 主动说话

| 配置项                              | 默认值  | 含义                                                   |
| ----------------------------------- | ------- | ------------------------------------------------------ |
| `proactive.enabled`                 | `true`  | 是否启用主动说话心跳                                   |
| `proactive.silenceThresholdSeconds` | `10800` | 沉默多久后才开始计算主动说话概率                       |
| `proactive.startProbability`        | `0.01`  | 刚跨过阈值时的概率                                     |
| `proactive.probabilityPerHour`      | `0.05`  | 每多沉默一小时概率的增量                               |
| `proactive.tickSeconds`             | `3600`  | 心跳间隔（秒）                                         |
| `proactive.allowGroups`             | `[]`    | 只在这些群里主动说话，逗号分隔；留空表示都不主动说话   |
| `proactive.allowUsers`              | `[]`    | 只在这些私聊里主动说话，逗号分隔；留空表示都不主动说话 |

- 白名单按聊天的类型分别生效：群看 `allowGroups`，私聊看 `allowUsers`；**两者默认都为空，表示不主动说话**。
- 会话覆盖里写死 `proactive: true` 的聊天不受白名单限制，写死 `false` 的一律不主动开口。
- 会话覆盖里的 `proactiveProbability` 是这个聊天单次心跳的触发概率，写了就用它，
  不再随沉默时长增长；沉默阈值对所有聊天一视同仁。
- 主动说话由配置放行的聊天自动触发，轮次按最低权限的 `proactive` 角色执行（工具档与普通聊天一致，
  不会拿到 `admin` 档的全工具）；因模型未发送而补的提醒沿用被提醒那一轮的角色。

## 出站限流

出站消息按目标（群 / 私聊）单独计数，避免模型一轮连发把群刷爆，也降低账号风控风险。

| 配置项                     | 默认值  | 含义                                               |
| -------------------------- | ------- | -------------------------------------------------- |
| `rateLimit.maxPerMinute`   | `8`     | 每分钟最多发多少条，超出则拒绝这次发送             |
| `rateLimit.maxPerHour`     | `60`    | 每小时最多发多少条，超出则拒绝这次发送             |
| `rateLimit.minGapMs`       | `1500`  | 相邻两次发送之间的最小间隔（毫秒），不足则先等一等 |
| `rateLimit.stall`          | `false` | 触顶时等窗口结束再发，而不是直接拒绝               |
| `rateLimit.stallMaxWaitMs` | `60000` | 最多等多久（毫秒），超过就直接拒绝                 |

- 三个计数相关的值都是 `0` 表示不限制。
- 拒绝时工具返回错误说明，模型会收到「请停止发送并结束本轮」；本轮同样算已回复，不会再触发补发提醒。
- 计数只在内存里，插件重启后重新开始；超长消息拆出的每一段都算一条。
- 同一段消息内部的多段共用一个操作 id：段与段之间只按发送间隔等待，不再叠加限流间隔。
- 插件自己生成的消息（`/emoji-label` 的结果与进度）走另一个计数域：它们只受间隔约束，不会占用模型回复的额度。
- `rateLimit.stall` 打开后，只有「每分钟」这一档会等窗口结束：等到最早的记录滑出窗口就立刻发，
  等待总时长不超过 `rateLimit.stallMaxWaitMs`。
- 「每小时」这一档始终直接拒绝，不会真的睡一小时——那等于把模型挂起一整小时。
- 等待超过上限时按拒绝处理，原因里写明还要等多久、允许多少。

## 出站敏感信息拦截

发给 QQ 的消息在发送前会扫一遍，命中凭证就整条拦下，不发送。

| 拦截对象     | 例子                                                             |
| ------------ | ---------------------------------------------------------------- |
| 各家 API key | GitHub、Anthropic、OpenAI、AWS、Slack、Stripe、npm 等            |
| 私钥与 JWT   | PEM 私钥块、`eyJ…` 令牌、`Authorization: Bearer …`               |
| 凭证赋值     | `password=…`、`api_key: …`、`密码：…`（含全角与零宽字符变体）    |
| 已知凭证     | 环境变量里名字像密钥的值、`napcat.token`，被拆开或编码也能认出来 |
| 凭证文件路径 | `~/.ssh/id_rsa`、`~/.aws/credentials`、`.env` 等                 |

- 只拦凭证，不拦邮箱、手机号、QQ 号、银行卡号这类群聊里正常出现的内容。
- 命中后工具返回错误，模型可以删掉凭证后重发；本轮不会记为已回复，也不会触发补发提醒。
- 检查在拆分发送之前做，超长消息只要有一段命中，整条都不发。
- 已识别的凭证不会出现在日志与错误说明里，只记录命中的检测器名称。
- `sensitive.enabled` 设为 `false`（或 `QQ_SENSITIVE_ENABLED=0`）可以关闭。

## 日志

日志同时写两处：console 保留人类可读的格式，文件写一行一条的 JSON。

| 配置项         | 默认值       | 含义                                          |
| -------------- | ------------ | --------------------------------------------- |
| `log.level`    | `info`       | 日志级别：`debug` / `info` / `warn` / `error` |
| `log.dir`      | XDG 日志目录 | 日志文件目录                                  |
| `log.maxSize`  | `5m`         | 单个日志文件的大小上限                        |
| `log.maxFiles` | `5`          | 保留多少个历史日志文件                        |

- `log.dir` 为空时使用 `$XDG_STATE_HOME/opencode-qq-bot/logs`；
  未设置 `XDG_STATE_HOME` 时使用 `~/.local/state/opencode-qq-bot/logs`。目录不存在会自动创建。
- 日志文件按天滚动，名为 `qq-bot-YYYY-MM-DD.log`；超过 `log.maxSize` 就再切一份，
  历史最多保留 `log.maxFiles` 份。
- 写盘前会对整行做一次脱敏（与出站拦截用同一套检测器）：识别到的凭证会被替换成
  `[REDACTED:<检测器>]`，`message`、`meta` 里的 Error stack 一并覆盖。
- 脱敏只打码不拦截：普通中文聊天、QQ 号、手机号、邮箱、URL、UUID 原样保留。
- 插件卸载时会等文件流落盘，避免丢掉最后几行日志。

## 调用链追踪

一条入站消息拿一个 `trace_id`，事件接收、模型起跑、模型处理、出站回复各记一个节点，
事后按 `trace_id` 就能把这一轮串起来。

| 配置项                | 默认值       | 含义                     |
| --------------------- | ------------ | ------------------------ |
| `trace.enabled`       | `true`       | 是否记录调用链追踪       |
| `trace.dir`           | 与日志同目录 | 追踪文件目录             |
| `trace.maxSizeMb`     | `80`         | 追踪文件总容量上限（MB） |
| `trace.retentionDays` | `7`          | 追踪文件保留天数         |

- 节点按天写进 `qq-bot-traces-YYYY-MM-DD.jsonl`，一行一个 JSON。
- 只记元数据（目标、消息号、字数、模式），不记消息正文。
- 超过保留天数的文件在启动时删掉；总容量超了先删最旧的文件。写满又清不出空间时丢弃新记录并告警。
- 追踪目录按 `0700` 创建，文件按 `0600` 写入。
- 相关日志会带上 `trace_id`，可以按它把日志与追踪文件对起来。
- `trace.enabled` 设为 `false`（或 `QQ_TRACE_ENABLED=0`）可以完全关闭。

## 出站媒体路径

`qq_send_image` / `qq_send_record` 的 `file` 只接受白名单目录里的本地文件，
或者插件能下载的公网地址。

| 允许的目录     | 来源                                            | 说明                         |
| -------------- | ----------------------------------------------- | ---------------------------- |
| 机器人工作目录 | 固化（`home` 指向的目录）                       | 模型 `write` / `bash` 的产物 |
| 媒体目录       | 固化（`$XDG_STATE_HOME/opencode-qq-bot/media`） | 入站图片缓存、下载的远端媒体 |
| 额外目录       | `media.allowedDirs`（`QQ_MEDIA_ALLOWED_DIRS`）  | 用户自己的图库 / 语音库      |

- 判定时会展开 `~`，相对路径按机器人工作目录解析，再取真实路径比较：
  目录里的软链接指向目录外同样拒绝。
- 按目录边界比较：`/data/qq-bot` 不会命中 `/data/qq-bot-secret`。
- 必须是存在的普通文件；路径不合法时不占发送额度，模型可以换个文件重发。
- http(s) 地址由插件预检：协议与端口要在白名单里，域名解析出的每个地址都必须是公网；
  通过后地址原样交给 NapCat 去下载，插件不碰文件（NapCat 与插件不必共享文件系统）。
- 预检只解析一次 DNS，NapCat 下载时会再解析一次，中间存在 DNS 重绑定窗口。
- `media.allowedDirs` 默认为空：除工作目录与媒体目录外，其它目录都要显式放开。

## 工具权限与配置档

工具按「发送者角色 + 聊天」分配，配置默认读当前工作目录下的 `tool-profiles.json`
（`toolProfilesPath` / `QQ_TOOL_PROFILES` 可改路径，模板见 `tool-profiles.example.json`）。

| 配置项             | 说明                                                          |
| ------------------ | ------------------------------------------------------------- |
| `ownerQQ`          | 所有者 QQ。私聊永远放行，管理命令只在它的私聊生效             |
| `admins`           | 管理员 QQ 列表，拥有全部工具权限；私聊还需在准入名单里        |
| `toolProfilesPath` | 配置文件路径，空表示 `tool-profiles.json`（相对当前工作目录） |

| 角色           | 使用的配置档                                        |
| -------------- | --------------------------------------------------- |
| owner / 管理员 | `admin`                                             |
| 其他人         | `chats[<目标>]` 指定的档，未指定用 `defaultProfile` |

- `allow` 就是白名单：没列出的工具一律不可用；支持 `*` 与 `qq_*` 这类通配；`deny` 优先于 `allow`。
- 内置默认档：`chat` 只放行 `websearch`、`webfetch` 与 `qq_*`（其余含 `shell` / `write` / `read` / 子代理全部拒绝）；
  `readonly` 只留读取与 `qq_*`；`admin` 全开。只写自己关心的档时，其余档沿用内置默认值。
- 普通成员不带子代理的原因：它会开一个不受聊天约束的新会话（工具 id 在不同版本是 `subagent` 或 `task`）。
  QQ 会话里创建子代理一律拒绝，即使当前配置档放行。
- owner / 管理员固定用 `admin` 档，`chats[<目标>]` 只对普通成员生效。
- 管理员要能收到消息，私聊还得在 `access.allow.users` 里；`ownerQQ` 的私聊不受名单限制。
- 文件缺失、语法错误或写到一半时沿用上一份可用配置并告警；按 mtime 热加载，下一轮生效。
  写入方应使用临时文件 + rename，避免读到半截内容。
- 限制分两层：`context` 钩子里删掉不允许的工具，`execute.before` 再挡一次，
  Code Mode、并发调用也绕不过去；被拒绝时模型收到中文错误。

## 会话覆盖

每个群 / 私聊可以单独改唤醒方式、是否主动说话、用哪个 agent、模型和角色设定。
配置默认读当前工作目录下的 `chat-overrides.json`
（`chatOverridesPath` / `QQ_CHAT_OVERRIDES` 可改路径，模板见 `chat-overrides.example.json`）。
这是全局配置之外的另一层：文件里写出的字段覆盖对应的全局项，没写的继续用全局值。

| 配置项              | 说明                                                           |
| ------------------- | -------------------------------------------------------------- |
| `chatOverridesPath` | 配置文件路径，空表示 `chat-overrides.json`（相对当前工作目录） |

### 全局项与会话项对照

| 会话字段               | 覆盖的全局项                                                  | 取值                                  | 说明                                                       |
| ---------------------- | ------------------------------------------------------------- | ------------------------------------- | ---------------------------------------------------------- |
| `wake`                 | `wake.*`                                                      | `all` / `mention` / `prefix` / `none` | 群聊的唤醒条件                                             |
| `prefix`               | `wake.prefixes`                                               | 字符串                                | `wake` 为 `prefix` 时使用的前缀                            |
| `proactive`            | `proactive.enabled`                                           | 布尔                                  | `false` 关闭该聊天的主动说话；不写时跟随全局               |
| `proactiveProbability` | `proactive.startProbability` / `proactive.probabilityPerHour` | 0 到 1                                | 该聊天单次心跳的触发概率，不写时用全局公式                 |
| `agent`                | `agent`                                                       | 字符串                                | 覆盖该聊天使用的 OpenCode agent                            |
| `model`                | `model`                                                       | `provider/model[/variant]`            | 覆盖该聊天使用的模型                                       |
| `soul`                 | `soulPath` / `soulName`                                       | 文件路径                              | 覆盖该聊天使用的角色设定文件，相对路径按机器人工作目录解析 |

### 覆盖行为

- `wake`：`all` 每条消息都必回，`mention` 被 @ 才必回（默认），
  `prefix` 命中前缀或被 @ 才必回，`none` 这个群完全不响应群消息。
- `wake` / `prefix` 只作用于群聊；私聊永远回复，不受这两项影响。
- `proactive` 只能把该聊天的主动说话关小：`false` 一定不主动开口；不写时跟随
  `proactive.enabled`；全局 `proactive.enabled` 为 `false` 时心跳不运行，会话写 `true`
  也不会重新开启。`wake: none` 同样会关掉主动说话。
- `proactiveProbability` 是这个聊天单次心跳的触发概率（0 到 1），写了就用它，
  不再随沉默时长增长；没写就按全局公式算。沉默阈值两边一视同仁。
- `agent` / `model` 覆盖优先于全局配置：会话首次建立时直接带上覆盖值，之后覆盖变化时
  对已有会话调用 `switchAgent` / `switchModel` 切换，值没变就不切。
- `soul` 覆盖 `soulPath` / `soulName` 选出的默认文件，按 mtime 热加载，改完下一轮生效。
- 必回与否写进提示词：命中时明确要求模型回复，没命中时允许它不回复；
  群里第一条 @ 的是别人时，提示词会明确说「这条消息不是在跟你说话，不要回复」。
- 文件缺失按默认走；单个字段写错只忽略这一项并告警；整份文件解析失败沿用上一份配置。
- `/status` 会列出每个聊天的唤醒方式与主动说话开关。

## 管理命令

同一组命令也注册为 TUI 命令，两边共用一份实现；TUI 侧命令加 `qq-` 前缀
（`/qq-help`、`/qq-status`、`/qq-reset`、`/qq-tools`、`/qq-emoji-label`），避免与 OpenCode 内置命令冲突。
`/help` 直接由命令表生成，表情标注也在其中。
QQ 侧只在 `ownerQQ` 与 `admins` 各自的私聊里生效，
且发送者必须是该私聊的主人；群里、其他人的私聊、未知的 `/xxx` 都照常交给模型。
TUI 侧执行时结果发到该会话绑定的 QQ 聊天，没有绑定就发第一个配置目标。

| 命令                            | 作用                                                 |
| ------------------------------- | ---------------------------------------------------- |
| `/help`                         | 命令说明                                             |
| `/status`                       | 各聊天的会话、队列与重试状态                         |
| `/reset`                        | 列出放行名单里的聊天，不执行重置                     |
| `/reset group:123`              | 先打断执行中的回合并删除该聊天的会话，下一条消息重开 |
| `/tools [group:123]`            | 查看配置档与可用工具                                 |
| `/emoji-label [all\|inc\|list]` | 给收藏表情生成中文标签（TUI 侧是 `/qq-emoji-label`） |

- `/reset` 只列出并接受放行名单里的目标；名单外的群号不会留下状态条目，也不会被重置。

## 通知事件订阅

| 配置项             | 环境变量             | 默认值    | 说明                                  |
| ------------------ | -------------------- | --------- | ------------------------------------- |
| `events.subscribe` | `QQ_EVENT_SUBSCRIBE` | `message` | 订阅的事件类别：`message` / `notice`  |
| `events.notices`   | `QQ_EVENT_NOTICES`   | `[]`      | `notice` 里关心哪些通知，留空表示全收 |
| `events.inject`    | `QQ_EVENT_INJECT`    | `true`    | 通知是否注入会话上下文                |

- 类别列表与通知列表都用逗号分隔，写错的类别会被忽略并告警。
- `events.notices` 可以写通知类型（`group_recall`），也可以写类型加子类型（`notify.poke`）；
  列表为空表示这一类通知全收。
- 通知只写日志与上下文，不会自己发起一轮对话；每个聊天最多缓存 20 条、等待 30 分钟。

## 角色设定

角色设定放在机器人工作目录的 `souls/` 里，可以放多份，`soulName` 选生效的那份，
`soulPath` 可以覆盖成任意文件或目录。工作目录见 `home`（默认 XDG 工作区）。

| 情况            | 生效文件                                          |
| --------------- | ------------------------------------------------- |
| 只配 `soulName` | `<工作目录>/souls/<soulName>`                     |
| 只配 `soulPath` | 该路径指向的文件；指向目录时取目录下的 `soulName` |
| 两个都配        | `soulPath` 优先                                   |
| 都没配          | `<工作目录>/souls/default.txt`                    |

- `soulName` 默认 `default.txt`。
- 首次启动时把随包分发的初始文件复制到工作目录；已有的同名文件不会被覆盖，升级插件不影响改过的设定。
- `soulPath` 与 `soul` 的相对路径都按机器人工作目录解析，与加载插件的项目目录无关。
- 文件内容改动会被监听，下一轮立即用新设定；文件稍后创建也会被捡到。
- 换角色改 `soulName`：写进 `opencode.json(c)` 保存后 OpenCode 重载插件后生效。

## 图片文件

OpenCode 的附件只接受 `file:` 与 `data:`。远端图片会先下载到受控临时目录
（`$XDG_STATE_HOME/opencode-qq-bot/media`，未设置时 `~/.local/state/opencode-qq-bot/media`），
再以 `file:` 引用交给会话，避免 base64 字符串进入插件缓存和每轮 prompt。

| 限制             | 值   | 说明                                   |
| ---------------- | ---- | -------------------------------------- |
| 单张图片字节上限 | 5MB  | 超过则只保留 `[图片]` 占位文本         |
| 单轮图片数量上限 | 8 张 | 超出部分只保留占位文本                 |
| 单轮图片字节总量 | 16MB | 按原始字节计算，超出部分只保留占位文本 |
| 临时文件保留时间 | 7 天 | 过期文件由插件定期清理                 |

单轮提示指一条消息渲染出来的附件，以及会话空闲时合并多轮消息后的附件。
超出限制的图片不会下载，只有占位文本会进入提示词。
下载使用 15 秒超时、拒绝重定向、拒绝本机与内网地址，并按魔数校验图片类型。
